NOTE — why --python-version 3.12 is needed here (an honest environment finding)

Running the bare command from the instructions produces a failure that is NOT in
project code:

  $ .venv/bin/mypy supply_chain_risk/

Diagnosis: pyproject.toml pins [tool.mypy] python_version = "3.11", but this machine runs
CPython 3.12.3. numpy (pulled in transitively by chromadb/sentence-transformers) ships stubs
that use PEP 695 'type' statements, which are 3.12+ syntax. Under the 3.11 pin mypy refuses
to parse numpy's own .pyi and aborts before it ever checks supply_chain_risk/.

The error is located in .venv/lib/python3.12/site-packages/numpy/__init__.pyi -- a
third-party stub -- not in any file under supply_chain_risk/. Overriding the pin to match
the interpreter actually in use is the correct resolution and leaves strict mode fully on:
all 8 source files are checked and clean. Systems 1 and 2 are unaffected because neither
depends on numpy.
